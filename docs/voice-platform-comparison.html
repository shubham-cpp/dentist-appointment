Twilio ConversationRelay versus two Telnyx voice paths

A decision report for an American-English virtual receptionist that answers inbound calls, schedules appointments, transfers callers, and connects to dental systems.

Currency: USD Model for custom paths: OpenAI GPT-5.6 Luna through AI SDK and OpenRouter Excluded: infrastructure and recording

Start with Telnyx AI Assistants

It gives Brightview the fastest production path. Start with Telnyx's native managed GPT-5.6 Luna option. Keep appointment authority in Brightview's backend.

Keep custom TeXML media as the control fallback. Use it when raw-audio control or savings justify a voice-infrastructure team. Choose Twilio when its ecosystem, telemetry, or contracts outweigh its higher price.

Build the domain authority in Brightview

The model may request slots. Brightview must validate availability, identity, appointment type, provider, and idempotency before any write.

Exact meaning of “Telnyx + TeXML” in this report

It means a TeXML application using bidirectional <Stream> media. Telnyx supplies telephony and audio transport. Your runtime supplies STT, TTS, endpointing, buffering, interruption, the model, tools, and recovery.

This is not a simple <Gather>/<Say> IVR. It is also not Telnyx ConversationRelay. That product would overlap the managed speech boundary already represented by Twilio. See the TeXML Stream reference.

Trial latency targets

First greeting
Answer to audible speech: p50 under 1.0 second and p95 under 1.5 seconds.
Tool-free turn
Caller speech end to first audible reply: p50 under 0.8 seconds and p95 under 1.5 seconds.
Scheduling turn
One scheduling tool included: p50 under 1.2 seconds and p95 under 2.0 seconds.
Interruption
Speech stops promptly, the partial reply is recorded, and the task state remains correct.
How to compare latency fairly

Measure voice-to-voice latency from the end of caller speech to the first audible agent audio. Report p50, p95, failures, and interruption recovery.

Keep caller regions, carrier routes, prompts, tools, model, voice quality, and concurrency equal. Separate endpointing, STT, model time-to-first-token, tool time, TTS, and network time.

Twilio exposes STT, application, TTS, and network timing in ConversationRelay Insights. Telnyx exposes component and cost breakdowns through Session Analysis. Sources: Twilio relay summary and Telnyx Session Analysis.

Latency sources and caveats

Twilio's product page reports the median and p95 figures. Its documentation also recommends streaming text tokens immediately. Telnyx publishes a 450 ms architecture budget for a co-located stack, but warns readers to test the selected models, tools, and routes.

Custom GPT-5.6 Luna on each path

Twilio. AI SDK can stream GPT-5.6 Luna through OpenRouter. Your application owns tools and sends response text to the relay.

Telnyx TeXML. AI SDK owns the same model loop. Your application also converts model text into audio and sends it to the media stream.

Telnyx AI Assistant. Telnyx offers GPT-5.6 Luna as a native managed model. This needs no separate OpenAI key. Telnyx also accepts a public OpenAI-compatible endpoint.

Use native Luna when model choice is enough. Use an adapter only when Brightview must preserve exact AI SDK tools, state, authentication, or retry behavior.

Sources: Telnyx managed Luna release note, Telnyx custom LLM providers, Twilio Studio ConversationRelay, and OpenAI GPT-5.6 Luna.

Failure handling that changes the choice

Twilio does not automatically reconnect an unexpected ConversationRelay WebSocket disconnect. The session fails. Your action callback can return new TwiML to reconnect.

TeXML can reconnect its media WebSocket by default. Your code must prevent duplicate audio, stale state, and unsafe tool replay. A managed assistant removes your WebSocket from the speech loop.

Every option needs timeouts, idempotency keys, a no-write fallback, human transfer, and an after-call task when scheduling systems fail. Source: Twilio ConversationRelay error handling.

Reliability, support, and public limits

Twilio. Voice supports a fallback URL. Its public API SLA starts at 99.95%. Paid support starts at $250 monthly or 4% of spend. Speech-provider coverage can differ.

TeXML custom. TeXML supports primary and fallback webhooks. Media streams reconnect by default. Your runtime must detect replayed audio, restore state, and prevent duplicate tool writes.

Telnyx AI Assistant. The API exposes fallback configuration. Public pay-as-you-go pricing lists 500 concurrent calls. Confirm support response terms and complete-stack availability in the contract.

Sources: Twilio availability guidance, Twilio API SLA, Twilio support plans, TeXML fundamentals, and Telnyx Assistant API.

Minimum scheduling tool contract
  • identify_caller: verify the caller before returning appointment details.
  • list_slots: return a small, current set of eligible slot IDs.
  • hold_slot: create a short exclusive hold when the workflow needs one.
  • book_slot: recheck and commit only a previously offered slot.
  • transfer_to_staff: carry a reason code and a short safe summary.
  • send_confirmation: send after the scheduling transaction succeeds.

Recommendation by scenario

There is no universal winner. These are the conditions that should change the choice.

Fastest safe pilot

Choose Telnyx AI Assistant. Use a managed Telnyx model first. Keep scheduling writes behind Brightview tools.

GPT-5.6 Luna is mandatory

Choose Telnyx AI Assistant with native managed Luna. Use a custom endpoint only when exact AI SDK behavior is mandatory.

Exact AI SDK loop is mandatory

Choose Twilio first. It preserves custom streaming and tools without raw-audio work. Choose TeXML when full audio control or scale savings justify it.

Existing Twilio estate

Choose Twilio ConversationRelay. Existing numbers, Studio flows, support, staff knowledge, and negotiated rates can outweigh list-price differences.

Voice cloning matters most

Prefer Telnyx. Its Voice Design Lab and assistant integrations make custom voices a first-party workflow.

Lowest usage cost at scale

Choose TeXML custom media after a load test. Its component pricing is lowest. Add the cost of a voice-infrastructure team.

Lowest engineering risk

Choose the managed Telnyx assistant. It has the smallest voice-runtime code surface and simplest operating model.

Lowest vendor lock-in

Choose TeXML custom media. Keep audio providers, the model, and tools portable. Accept custom runtime maintenance.

Validation plan before selection

Run the same inbound call set on the managed Telnyx assistant and Twilio. Add TeXML when control or scale justifies the build.
